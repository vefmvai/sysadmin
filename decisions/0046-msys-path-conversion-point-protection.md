# 0046: Пути чужого сервера в нативных программах — точечная защита от конверсии MSYS, не глобальная

**Статус:** Принято
**Дата:** 2026-10-14
**Автор:** — (аудит агентом в режиме `/dev`, «ок» оператора на план задачи)

## Контекст

Оператор работает на Windows, скрипты скиллов исполняются у него в Git Bash (MSYS2). При запуске
**нативной** программы рантайм MSYS переписывает аргументы и переменные окружения, похожие на
POSIX-пути: `/root/x` → `C:/Program Files/Git/root/x`. Для локальных файлов это нужно, для путей
**другой машины** — порча. Замер правил — `knowledge/agent-runtime/_reference/msys-path-conversion.md`.

- 2026-10-14 регресс-тест входа `vless-tls` показал: путь сертификата сервера уходил в JSON для
  панели путём Windows (ADR-0045, отдельный PR; исправлено там же у одного вызова).
- Аудит всех локально исполняемых скриптов (~470 строк вызовов): ещё 8 мест риска — удалённые
  команды `ssh <хост> "/usr/local/x-ui/…"` (под Windows-овым ssh, которым оператор ходит на сервер),
  `jq` с `spiderX`/`path` чужого сервера и с секретами, начинающимися с `/`. Дефект уже проявился в
  данных: в разобранной подписке 2026-06 два пути стали `C:/Program Files/Git/api/v1/stream`.
- Рассматривался вариант `export MSYS_NO_PATHCONV=1` на весь скрипт или в общей библиотеке. Отвергнут:
  те же скрипты передают нативным программам **локальные** пути, которым конверсия нужна, — cookie-файл
  из `mktemp` для нативного `curl -b` в `scripts/lib-api/3xui.sh`, временные файлы, конфиги. Глобальное
  отключение сломало бы их — так же тихо.
- Статический линтер на общий случай не построить: конверсия срабатывает на **значении** аргумента
  во время выполнения, а не на тексте кода.

## Решение

Мы защищаем от конверсии **отдельный вызов** нативной программы, в который уходит путь или строка
чужого сервера, и в котором нет локальных путей:
`MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*' <программа> …` (на Linux/macOS переменные безвредны).
Удалённые команды `ssh` пишем одной строкой, не начинающейся с `/`, либо ставим тот же префикс.
Каждое такое место — с комментарием, почему префикс безопасен (нет локальных путей).

Регресс — `scripts/test-msys-path-conversion.sh`: разбор ссылок, сборка исходящего на заглушке API,
статическая проверка узкого класса `ssh <хост> '/…'`. Значим только под Git Bash (секция 0 сама
сообщает, переписывает ли среда пути); испытан на коде до правки — 5 провалов.

## Последствия

- ✅ Пути и секреты чужого сервера доходят как есть: spiderX, path, пароли, команды панели.
- ✅ Локальные пути (cookie-файлы, временные файлы) по-прежнему конвертируются — вход в панель цел.
- ⚠️ Новые вызовы надо защищать руками; страховка — заметка в `agent-runtime/_reference`, статическая
  проверка узкого класса `ssh` и регресс-тест. Общий класс линтер не ловит.
- ⚠️ Не закрыто: тело входа в панель `-d "username=…&password=…"` (тот же вызов несёт cookie-файл —
  префикс нельзя) — `todos/pending/2026-10-14-3xui-lib-api-generations.md`.
- ⚠️ Тест под Linux/macOS зеленеет и на сломанном коде — доказательная сила только под Git Bash.
