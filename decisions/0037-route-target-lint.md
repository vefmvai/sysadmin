# 0037: Замок против ложного маршрута в README баз знаний

**Статус:** Принято
**Дата:** 2026-08-05
**Автор:** —

## Контекст

`.claude/knowledge/*/README.md` с этапа 4Б плана context-engineering работает
**маршрутизатором**, а не каталогом: строка таблицы отвечает на вопрос читателя
(«HTTP 403 при входе в панель») именем файла и номером раздела. Смысл конструкции в том,
что агент идёт по маршруту **не перепроверяя** — иначе экономии контекста нет.

Отсюда цена ошибки: ложный маршрут не просто бесполезен, он вреден вдвойне. Агент тратит
контекст на чтение не того файла и выносит ложный вывод «ответа в базе нет».

**Что произошло 05.08.2026.** Три круга независимой проверки этапа 4Б дали FAIL, FAIL,
FAIL. Семь дефектов из внесённых починками относились к одному классу — **утверждение
о содержимом файла без сверки с содержимым**. Худшие случаи:

- строка про DNS отправляла в `_reference/routing-server-3xui.md`, где **ноль** упоминаний
  DNS, резолвинга и DoH. Маршрут был выведен из общих соображений: «маршрутизация на
  сервере — значит, и DNS там»;
- та же строка обещала термин `DoU`, которого нет ни в одном из 27 файлов базы;
- строка обещала «российские домены мимо зарубежного резолвера», а единственное место, где
  это было описано, закрыто HTML-комментарием и мертво;
- две строки обещали содержимое, вынесенное в скиллы соседним коммитом.

**Почему это не ловилось.** `validate-knowledge.py` проверяет **существование пути**:
frontmatter, слой, TTL, битые ссылки, сироты. Он был 🟢 все четыре круга. Содержимое по
ссылке он не смотрит и смотреть не обязан — это разные задачи.

Правило репозитория «правило, нарушенное дважды, идёт в код» выполнено с запасом: семь раз
за три круга, причём дважды подряд дефект попадал в текст **под видом исправления
предыдущего дефекта того же класса**.

Рассматривался альтернативный вариант — «просто быть внимательнее» и «добавить пункт в
чек-лист `/dev`». Отвергнут: три круга проверки чужими руками показали, что внимательности
не хватает именно там, где правка выглядит очевидной.

## Решение

Мы вводим линтер `scripts/check-route-targets.sh`, подключённый к `.githooks/pre-commit`
на коммитах, трогающих `.claude/knowledge/`. Он проверяет два свойства маршрута:

- **R1 — номер раздела.** Маршрут ссылается на `§N` (или диапазон `§N-§M`) — заголовок с
  этим номером обязан существовать в целевом файле.
- **R2 — словарь.** Хотя бы один технический термин из левой колонки (латиница длиной ≥3,
  за вычетом короткого списка шумовых слов) обязан встречаться в целевом файле. **Каждая
  цель проверяется отдельно**: если у строки два адреса, соседний адрес с нужным словом
  не оправдывает мёртвый.

Порог R2 намеренно слабый — «хотя бы один термин». Более строгий порог (доля совпавших
терминов) даёт ложные срабатывания на строках, где вопрос сформулирован шире раздела, а
парализующий замок снимут через день.

## Последствия

- ✅ Класс «маршрут в файл, где темы нет» закрыт кодом. Историческая дефектная строка из
  коммита `761366c` блокируется — это секция [1] теста, и данные она берёт **из истории
  git**, а не из головы автора (правило 2 `building-enforcement.md`).
- ✅ Мёртвый номер раздела ловится точно, без порогов и эвристик.
- ✅ Строки, где проверить нечего (вопрос целиком по-русски, технических терминов нет),
  помечаются «непроверяемо» и печатаются **явно**. Молчаливого пропуска нет: на живом
  README таких 10 из 32.
- ⚠️ **НЕ ловит смысловую инверсию.** Строка «маршрут в direct, резолвинг через VPN» при
  разделе, где написано ровно наоборот, проходит: оба слова в файле есть. Это реальный
  дефект круга 3, и он остаётся за чтением человека.
- ⚠️ **НЕ ловит отсутствующий маршрут.** Тема, потерявшая строку, замку невидима — ему
  нечего проверять. Это второй реальный дефект круга 2 (регрессия маршрута к «что такое
  TUN»), и он тоже остаётся за проверкой прогоном запросов.
- ⚠️ Треть строк живого README непроверяема правилом R2. Цифра печатается в отчёт, чтобы
  никто не принял «✅ чисто» за полное покрытие.
- ⚠️ Замок разбирает markdown построчно и, как остальные замки репозитория, не отличает
  упоминание от значения (ADR-0028, правило 4 `building-enforcement.md`). Цена лишней
  остановки — одна реплика.

**Как проверен.** Тест `scripts/test-route-targets.sh`, 17 проверок в пяти секциях:
настоящий дефект из истории git; фикстура обхода (термины без совпадений, несуществующий
файл, мёртвый §N, мёртвый конец диапазона, разметка вокруг терминов); обратная сторона —
четыре заведомо корректных входа; парсер (строка каталога, не-табличная строка, таблица
скиллов); границы (пустой файл, несуществующий аргумент, путь с пробелом и кириллицей).

Первый прогон теста провалил **4 проверки из 17** — в том числе главную, историческую:
исходная версия сверяла термины с объединением целей, и вторая цель прикрывала мёртвую
первую. Ни одну из четырёх поломок нельзя было увидеть чтением кода.
