# 0040: Проверка обновлений мозга — хук SessionStart, а не проза

**Статус:** Принято
**Дата:** 2026-09-15
**Автор:** оператор (поручение «нормальная доработка» по находке 15.09.2026); реализация — режим `/dev`

## Контекст

Шаг 5.5 Cold Start обещает: раз в сутки агент сам проверяет, не вышел ли релиз мозга
новее установленного, и предлагает «обнови sysadmin» одной строкой. Обещание повторено в
ядре (§7.1), `README.md`, `INSTALL.md`, `UPGRADE.md`.

Проверка 15.09.2026 на машине оператора показала, что обещание не исполнялось:

- **Исполнять было нечего.** В `cold-start.md` алгоритм записан прозой внутри
  bash-блока, а на месте запуска стоит заглушка `: # placeholder для запуска фонового
  агента`. Запись метки `.update-check` — тоже в комментарии. Метки на машине оператора
  не было ни одной: проверка не выполнялась ни разу.
- **Алгоритм спрашивал не тот репозиторий.** Канон делал `git fetch origin --tags`. У
  оператора, который ведёт свою копию мозга, `origin` — личный приватный репозиторий, а
  релизные теги живут у `upstream` (репозиторий автора). Такая проверка честно отвечала бы
  «новых версий нет» при любом числе вышедших релизов.
- **Локальные теги уже однажды обманули проверку.** 06.08.2026 у оператора стоял свой
  тег `v2.4.0` на другом коммите, чем релиз автора с тем же номером; проверка по локальным
  тегам «врала» при старте.
- **Процедура применения была опасна для своей копии мозга.** «Обнови sysadmin» делала
  `git checkout --detach <тег>` для любой установки. На ветке со своими коммитами, которых
  нет в релизе, переключение на тег молча вывело бы их из работающего мозга.

Рассматривались варианты:

- **Усилить прозу в персоне** («не забудь проверить»). Отвергнут: именно проза и не
  исполнялась; добавлять байты в ядро на 98% бюджета ради того же — нечестно.
- **Фоновый субагент или фоновая команда по решению модели** (как описывал канон).
  Отвергнут: снова зависит от того, вспомнит ли модель; результат приходит «в следующем
  ответе», которого в короткой сессии может не быть.
- **Хук запускает сетевой запрос в фоне, результат показывается в следующей сессии.**
  Отвергнут: уведомление опаздывает на сессию, а отвязанные процессы ведут себя по-разному
  в Git Bash на Windows и в macOS — лишняя поверхность для поломок ради доли секунды раз в
  сутки (замер 15.09.2026 на машине оператора: `--status` против GitHub — 0,33 с).
- **`git fetch --tags` из хука.** Отвергнут: хук начал бы менять репозиторий при каждом
  старте и спотыкался бы о тег-двойник.

## Решение

Мы проверяем обновления **хуком `SessionStart`** (`.claude/hooks/brain-update-check.sh`,
подключён в `.claude/settings.json` с `matcher: "startup"` и `timeout: 20`), потому что
механизм движка исполняется при каждом старте, а проза — нет.

Правила хука:

1. **Раз в сутки.** Метка `.update-check` — секунды эпохи; пишется **до** сетевого запроса,
   чтобы упавшая проверка не повторялась на каждом старте. Метка прежнего формата (ISO) и
   метка «из будущего» считаются давними.
2. **Источник релизов:** `git config sysadmin.updateRemote` → `upstream` → `origin`.
3. **Теги — `git ls-remote --tags --refs`** прямо с удалённого: репозиторий не меняется,
   локальные теги в сравнении не участвуют. Ввод учётных данных запрещён сразу несколькими
   способами (`credential.interactive=never`, `GIT_ASKPASS=false`, `GIT_TERMINAL_PROMPT=0`),
   зависшая передача обрывается `http.lowSpeedTime`.
4. **Только релизные теги `vX.Y.Z`**, порядок по числам; из `VERSION` удаляются CRLF и
   BOM. Уведомление — только если релиз **строго новее**.
5. **Любой сбой — молчание с кодом 0.** Флаг `--status` отдаёт `REMOTE/LOCAL/LATEST/NEWER`
   для процедуры «обнови sysadmin» и при сбое возвращает код 1.

Вывод хука движок кладёт в контекст сессии; агент передаёт его оператору одной строкой
(Cold Start, Шаг 5.5). Хук сам ничего не обновляет.

**Процедура «обнови sysadmin»** берёт remote, последний тег и признак «новее» у того же
хука и выбирает путь по тому, есть ли в HEAD свои коммиты, которых нет в релизе:

- своих нет — прежний контракт `git checkout --detach <тег>`;
- свои есть, HEAD на ветке — слияние релиза в ветку (Yellow); конфликт — СТОП с показом файлов;
- свои есть, HEAD отсоединён — СТОП: сначала ветка, иначе коммит потеряется.

Сверх того процедура останавливается, если `git fetch --tags` отказал (локальный
тег-двойник даёт «would clobber existing tag»), и ничего не делает, если релиз не новее
установленного, в том числе когда мозг впереди релиза. Блок процедуры покрыт тестом,
который берёт код прямо из `cold-start.md`.

## Последствия

- ✅ Обещание «раз в сутки проверю сам» исполняется механизмом, а не памятью модели.
  **Живой прогон в движке** 15.09.2026 (Claude Code 2.1.224, Windows, `claude -p` в
  проекте-фикстуре с `VERSION` 0.0.1): хук отработал при старте (метка записана секундами
  эпохи), модель увидела уведомление в контексте и назвала обе версии.
- ✅ Своя копия мозга (личный `origin` + `upstream` автора) видит релизы автора.
- ✅ Проверка ничего не пишет в git и не зависит от локальных тегов.
- ✅ Два теста, оба испытаны на сломанных версиях, а не только на исправной:
  - `test-brain-update-check.sh` — 45 случаев. Прежний канон — 21 провал из 43 прогнанных
    (подключения в `settings.json` нет, два случая секции [8] не дошли), в том числе на трёх
    исторических дефектах (не тот remote, тег-двойник, отсутствие лимита и метки) и живой:
    его `fetch` вызвал askpass; первая версия хука — 4; хук с `exit 1` в конце — 14; хук без
    защиты от ввода — 5, из них один живой: askpass вызван.
  - `test-upgrade-procedure.sh` — 10 сценариев. Исходный канон — 5 провалов, первая версия
    новой процедуры — 4.
- ✅ Независимая проверка свежим контекстом (15.09.2026) нашла в первой версии шесть
  дефектов: BOM в `VERSION`, три слепых места теста (код возврата, защита от ввода,
  аннотированные теги) и четыре поломки процедуры — потеря своего коммита на отсоединённом
  HEAD, выкатка тега-двойника, «Готово» при конфликте слияния, откат мозга, опередившего
  релиз. Все исправлены и закреплены случаями в тестах.
- ⚠️ Раз в сутки старт сессии ждёт сетевой запрос. Худший случай — соединение, которое
  висит на этапе подключения или DNS: его обрывает только таймаут хука (20 с).
- ⚠️ `matcher: "startup"`: сессии, открытые через продолжение (`--resume`, `--continue`) или
  после `/clear`, проверку не запускают — её сделает следующий обычный старт. Шире не
  открыто сознательно: поведение фильтра для других значений не проверено, а ошибка в нём
  означала бы хук, который не срабатывает никогда.
- ⚠️ Хук проекта срабатывает, только когда сессия открыта в папке мозга (основной вход,
  ADR-0015). При вызове `@sysadmin` из чужой папки агент запускает скрипт сам — это
  снова дисциплина, а не механизм.
- ⚠️ Показ уведомления оператору по-прежнему делает модель: хук гарантирует, что факт
  попадёт в контекст, но не что модель его перескажет.
- ⚠️ Не проверено живым тестом: SSH-remote; git, не знающий `credential.interactive`
  (от него страхует `GIT_ASKPASS=false`); macOS и Linux — переносимость оценена чтением
  кода, машины для прогона не было; ветка «вход — терминал» в хуке.
- ⚠️ На Windows без Git Bash движок запускает хуки через PowerShell, где команда из
  `settings.json` не выполнится, — так же, как у остальных хуков репозитория.
