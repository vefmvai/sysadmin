# Sysadmin Agent — твой персональный сисадмин в чате

Готовый агент для Claude Code, который берёт на себя серверную рутину: настройку,
безопасность, бэкапы, мониторинг, деплой, расследования. Ты пишешь нормальными
фразами вроде «проверь сервер» или «настрой бэкапы» — агент сам выбирает нужную
процедуру и выполняет её, объясняя каждый шаг и не делая ничего опасного без твоего
подтверждения. Семь необратимых процедур (деплой, миграция, восстановление из бэкапа,
ротация секретов, первичная настройка и чистка сервера, установка мониторинга) агент
сам не запускает — он распознаёт задачу и подсказывает команду, а запускаешь ты (ADR-0027).

**Для кого.** Для людей, которые создают IT-продукты с помощью ИИ (вайбкодеров),
имеют один-два собственных сервера и не хотят тратить месяцы на изучение
сисадмин-профессии или нанимать фрилансера за деньги.

**Открытый продукт.** Бери, клонируй, настраивай под
свой проект — всё открыто, ничего не скрыто за облачной подпиской.

## Установка — одна команда в Claude Code

Открой Claude Code в любой папке и напиши:

> **Установи агента sysadmin из репо `https://github.com/vefmvai/sysadmin` по инструкции в INSTALL.md.**

Claude всё сделает сам:

1. Клонирует репо себе на машину (спросит куда).
2. Создаст рядом папку `infra/` для твоих данных (карта серверов, ADR, knowledge).
3. Создаст «bridge»-файл, чтобы `@sysadmin` работал из любого проекта.
4. Запустит интервью `/sysadmin-init` — 6 вопросов про твой проект (язык, менеджер паролей, сервер, мониторинг, бэкапы). На выходе — два твоих личных конфига: `agent-config.json` (мозг агента, в `sysadmin/`) и `infra-config.json` (карта инфры, в папке `infra/`).
5. Опционально предложит `/sysadmin-meet` — ~20-минутное знакомство с агентом (рекомендую если впервые видишь).

После этого **открой папку `sysadmin/` в Claude Code** — в терминале `cd sysadmin && claude`,
либо открой её в IDE-расширении / desktop-приложении — и сразу пиши обычными фразами:

```
привет, познакомься с моим сервером
```

Ты **уже говоришь с сисадмином** — отдельную команду-вызов запоминать не нужно: персона
загружается из `CLAUDE.md` при открытии папки (вход 2.0, ADR-0015). Агент сам поймёт, что
делать, и сам выберет нужный скилл — кроме семи необратимых, которые запускаешь ты явной
командой (ADR-0027).

Работаешь из **другого** проекта и хочешь позвать сисадмина оттуда? Два пути: подключи папку
агента через `/add-dir <путь-к-sysadmin>`, либо вызови разово `@sysadmin <запрос>` — для этого
и создаётся bridge-файл (шаг 3).

**Системные требования:** macOS / Linux / Windows · `git` · `jq` · Claude Code.

**Обновления.** Агент сам раз в сутки проверит новые версии и предложит обновиться. Или скажи в любой момент «обнови sysadmin» — он подтянет свежий релизный тег (`git fetch` + переключение на тег), покажет changelog и попросит подтверждение перед применением. Что сделать руками при переходе между версиями — `UPGRADE.md`.

**Удаление.** `rm -rf <папка-sysadmin> ~/.claude/agents/sysadmin.md`. Папка `infra/` (твои данные) останется — её удалишь руками если нужно.

## Что внутри

### Агент-персона

Ядро персоны живёт в **`CLAUDE.md`** репозитория (≈390 строк; загружается при открытии папки —
вход 2.0, ADR-0015) + 9 references-документов в `.claude/agents/references/` — это «мозг»
агента: ценности, конституция (что нельзя нарушать ни при каких обстоятельствах), характер,
протоколы работы, три зоны безопасности, ритуал памяти, реакции на VPN-сценарии. Файл
`.claude/agents/sysadmin.md` остаётся тонкой заглушкой-указателем (для `@sysadmin` из чужих
папок). Всё открыто и читаемо — никакого чёрного ящика. Размер ядра под бюджетом (≤ 42 КБ,
`wc -c`, проверяется pre-commit — ADR-0016; поднять бюджет можно только осознанным ADR).

### 22 готовых скилла

Каждый скилл — это отдельная процедура для типовой задачи. Агент сам выбирает
нужный скилл по твоей фразе. Исключение — семь скиллов, необратимо меняющих боевую
систему (`deploy-service`, `rotate-secrets`, `migrate-server-to-server`,
`bootstrap-new-server`, `cleanup-existing-server`, `install-monitoring-stack`,
`restore-from-backup`): их агент не запускает по своей инициативе, а называет тебе
команду (ADR-0027).

| Группа | Скиллы | Когда нужно |
|---|---|---|
| **Знакомство и настройка** | `/sysadmin-meet`, `/sysadmin-init` | Первый раз: знакомство → настройка под проект |
| **Настройка с нуля** | `/bootstrap-new-server`, `/setup-secrets-vault`, `/setup-backups`, `/install-monitoring-stack` | После покупки нового VPS |
| **Сеть и обход блокировок** | `/setup-vpn-panel`, `/extract-subscription-servers`, `/configure-vpn-routing`, `/setup-server-proxy`, `/generate-client-config`, `/refresh-vpn-knowledge` | Свой VPN-узел, извлечение серверов из закрытой (зашифрованной/HWID-locked) подписки, маршрутизация через подписку/свой загр.VPS, серверный прокси для программ, vless-ссылки и QR для устройств, актуализация knowledge раз в месяц (блокировки меняются) |
| **Текущая работа** | `/health-check`, `/inventory-scan`, `/deploy-service`, `/restore-from-backup` | Регулярно — утренний обход, обновления, диагностика, восстановление из бэкапа и плановый restore-тест |
| **Безопасность** | `/audit-security`, `/rotate-secrets` | Раз в квартал + при подозрении на проблему |
| **Спецоперации** | `/cleanup-existing-server`, `/migrate-server-to-server` | Унаследованный хаос или переезд на другой провайдер |

Подробное описание каждого — в `/sysadmin-meet` (часть 3) или в `.claude/skills/<имя>/SKILL.md`.

### Честно о глубине: где специализирован, где операционно компетентен

Чтобы не продавать «эксперта во всём» — где какая глубина на самом деле:

- **Специализация (глубокая, с отдельной базой знаний): VPN и обход блокировок РФ-2026.**
  Доменная база `.claude/knowledge/networking/` (3 слоя по TTL, ежемесячная актуализация
  через `/refresh-vpn-knowledge`), 6 профильных скиллов, рефлексы под TSPU / 3X-UI / sing-box.
  Это то, ради чего агент создавался, и где он сильнее всего.
- **Операционная компетентность (надёжные процедуры, без отдельной базы знаний):** базовая
  настройка VPS, Docker/compose, бэкапы (restic + проверенный restore), мониторинг, секреты,
  аудит безопасности, деплой, миграция. Здесь агент закрывает большую часть рутины одного
  оператора готовыми скиллами и общими SRE-навыками — но это не узкоспециализированный тюнинг.
- **Базовый уровень (через скиллы + общая эрудиция, не глубокий тюнинг): БД и nginx.**
  Диагностика, дампы, типовые конфиги — да; тонкая оптимизация запросов PostgreSQL или
  сложные nginx-сценарии под нагрузку — нет: тут агент честно скажет «это за моим профилем,
  нужен профильный специалист», а не сымитирует экспертизу.

Если задача за пределами — агент не блефует: говорит прямо и, если она повторяющаяся,
предлагает оформить её в новый скилл (режим разработки мозга — `/dev`).

### Inventory — паспорт твоей инфраструктуры

Папка `infra/inventory/` хранит актуальное состояние сервера: контейнеры, домены, базы данных, сети, тома, cron-задачи, автоматизации, TLS-сертификаты + **до 5 mermaid-диаграмм** (общая топология, Docker-сети, маршрутизация доменов, VPN-архитектура, карта автоматизаций). Это не статичная документация — агент сам обновляет её через `/inventory-scan` и при любом архитектурном изменении на сервере.

Inventory **живёт в твоей приватной папке `infra/`**, не в этом публичном репо. У каждого оператора своя инфраструктура и свои данные. Связь между публичным мозгом (этот репо) и твоей `infra/` — через реестр проектов `projects[]` в `agent-config.json` (см. ниже): каждый проект указывает на свою папку инфры через `infra_root`.

### Два конфига — мозг агента и карта инфры (ADR-0013)

Настройка живёт в **двух** файлах с разными ролями:

- **`agent-config.json` — мозг агента.** Живёт **в `sysadmin/`** (дом агента). Описывает самого агента: имя оператора, язык, менеджер паролей, реестр проектов (`projects[]` — какие у тебя есть инфраструктуры и где каждая живёт) и какой проект активен по умолчанию (`default_project`).
- **`infra-config.json` — карта инфры.** Живёт **в твоей папке `infra/`** (рядом с `inventory/`). Описывает конкретный сервер: какие подсистемы включены (мониторинг, бэкапы, Telegram), какие серверы, секция VPN-блока, опциональное оглавление `map`.

Оба создаются через `/sysadmin-init` (он же мигрирует старый единый `sysadmin-config.json`, если он у тебя остался). Потом скиллы читают их перед работой.

В этом репо лежат только публичные **шаблоны и JSON-схемы** для валидации: `agent-config.example.json` + `agent-config.schema.json` и `infra-config.example.json` + `infra-config.schema.json`.

## Принципы работы

### Три зоны безопасности

Каждое действие на сервере агент классифицирует по одной из трёх категорий:

- **🟢 Зелёная — диагностика.** Что только смотрит, ничего не меняет (логи,
  состояние контейнеров, замер ресурсов). Делает самостоятельно, без вопросов.
- **🟡 Жёлтая — изменения с подтверждением.** Что меняет, но обратимо (запуск
  сервиса, правка конфига). Брифинг из 6 пунктов → пауза → твоё «ок» → выполнение.
- **🔴 Красная — необратимые операции.** Что может уничтожить данные навсегда
  (удаление БД, контейнера с volume). Четырёхшаговая процедура с дословным
  type-to-confirm. Защита от случайностей.

Подробнее — в `/sysadmin-meet` (часть 5) или в персоне (раздел 6 Trust Zones).

**Красная зона держится не на честном слове.** С версии 2.4.0 её подпирает замок:
`.claude/hooks/red-zone-guard.sh` перехватывает команду **до выполнения** и не выпускает
необратимую операцию, пока фраза подтверждения не появится в **твоих** сообщениях. Агент
её подделать не может — он пишет только свои реплики, а фраза ищется в твоих. Ничего
включать не надо: хук приезжает вместе с репозиторием (`.claude/settings.json`). Обоснование
и устройство — ADR-0022; тесты — `.claude/hooks/tests/test-red-zone-guard.sh`.

Изредка замок срабатывает вхолостую — когда опасная строка попала в безобидную команду
(например, ты обсуждаешь `rm -rf` в тексте). Агент скажет об этом прямо и обойдёт корректно,
не пряча операцию.

### Что агент НЕ делает

- Не пишет твоё приложение (код продукта — твой).
- Не делает бизнес-логику.
- Не работает с серверами в обход своих правил даже под давлением.
- Не делает ничего самовольно, что не входит в текущую задачу.
- Не заменяет твою голову — финальные решения за тобой.

> Две папки рядом, два независимых git-репо. Публичный `sysadmin/` — мозг агента,
> одинаковый у всех, кто его берёт. Приватный `infra/` — твои реальные данные,
> которые публиковать нельзя. Связь — через реестр `projects[]` в `agent-config.json`
> (мозг): каждый проект указывает на свою папку инфры через `infra_root`.

## Требования

- **Claude Code** ([как установить](https://docs.claude.com/en/docs/claude-code/setup))
- **Git**
- **`bash`** — единственное, что нужно обеспечить тебе самому:
  - **macOS / Linux** — `bash` уже встроен, ничего делать не надо.
  - **Windows** — поставь **Git for Windows** (он даёт Git Bash; без него Claude Code
    работает через PowerShell и скиллы агента не запускаются): `winget install --id Git.Git -e`,
    затем перезапусти сессию Claude Code.
- **`jq`** — агент ставит его сам. При первом запуске `/sysadmin-init` проверяет `jq` и, если
  его нет, доустанавливает: сначала через твой пакетный менеджер (brew/apt/dnf/winget/choco/…),
  а если менеджера нет — просто скачивает официальный бинарник `jq` под твою ОС. В конце
  настройки агент сам тестирует, что всё работает, и честно скажет, если что-то не вышло.
- **SSH-доступ** к твоему серверу
- **VPS** (виртуальный сервер) — любой провайдер по выбору. Минимум — 2 ГБ RAM
  если планируешь использовать мониторинг-стек.

> **Менеджер секретов по ОС:** macOS — Keychain (рекомендуется), Linux — pass / KeePassXC /
> Bitwarden, Windows — Bitwarden / KeePassXC. Выбор делается в `/sysadmin-init`.

## Безопасность

- **Секреты НИКОГДА не лежат в репозитории.** Только индекс — в файле
  `inventory/shared/access.md` твоей **приватной** папки `infra/` (создаст
  `/sysadmin-init`). Сами значения — в выбранном менеджере паролей.
- **Pre-commit hook** через gitleaks (рекомендуется настроить — см. `CONTRIBUTING.md`).
  Ловит случайные коммиты секретов.
- **Оба конфига** — в `.gitignore`: `agent-config.json` (мозг, в `sysadmin/`) и `infra-config.json` (карта, в `infra/`). Личные данные не попадают в репозитории; публикуются только обезличенные `*.example.json` + `*.schema.json`.
- **Конституция агента** запрещает выдумывать данные, обходить процедуры, делать
  деструктивы без явного подтверждения.

## Углубление

Когда захочешь разобраться глубже — карта в `/sysadmin-meet` (часть 7). Краткий
порядок чтения:

1. **`CLAUDE.md`** — ядро персоны и главный документ: ценности, конституция, характер,
   три зоны, протоколы (вход 2.0: открыл папку → ты сисадмин). Обязательно в первую неделю.
2. **`.claude/agents/references/*.md`** — полные протоколы персоны (читаются по триггеру из ядра)
3. **`.claude/skills/<имя>/SKILL.md`** — конкретный скилл, который тебя интересует
4. **`decisions/0000-template.md`** — шаблон ADR. Когда будешь принимать своё
   архитектурное решение — копируй шаблон в свою `infra/decisions/` и заполняй.
5. **[`research/`](research/README.md)** — на чём стоят решения по мозгу: конспекты внешних
   источников с датами. Свежее — [контекст-инжиниринг для Claude 5](research/context-engineering-2026-07/README.md)
   (июль 2026): 9 источников, [12 принципов описания мозга агента](research/context-engineering-2026-07/PRINCIPLES.md)
   и [разбор нашего мозга по ним](research/context-engineering-2026-07/GAP-ANALYSIS.md).
