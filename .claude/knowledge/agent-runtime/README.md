# Домен `agent-runtime` — среда, в которой живёт агент

Знания про **сам Claude Code как среду исполнения**, а не про инфраструктуру оператора:
формат транскрипта, механизмы принуждения (хуки), устройство настроек. Нужны тому коду,
который принимает решения по данным среды — замкам, гейтам, разборам сессий.

Слои по TTL — общий канон (ADR-0006): `_live/` 14 дней, `_reference/` 60, `_meta/` 365.
Здесь пока только `_reference/` — устройство среды меняется медленнее фронта борьбы с
блокировками, но быстрее «мета».

| Файл | О чём | Кто потребитель |
|---|---|---|
| [`_reference/claude-code-transcript.md`](_reference/claude-code-transcript.md) | как отличить голос человека от вставок движка в `.jsonl`; какая сессия «своя» (`cwd`, номер сессии у субагента — родителя); как искать по журналам, не положив машину, и почему прошлый отчёт субагенту передают в задании | `red-zone-guard.sh`, `inventory-sync-guard.sh`, разбор сессий |
| [`_reference/building-enforcement.md`](_reference/building-enforcement.md) | как строить замок, чтобы он работал: живой тест в обе стороны, тест из источника, конфликт разделителя, почему ложные срабатывания — цена, а не дефект | всякий, кто добавляет хук / линтер / гейт (`/dev`) |

**Читать по одному файлу, а не оба сразу.** Пишешь код, который разбирает реплики
человека, — открывай `claude-code-transcript.md`. Добавляешь новый замок и хочешь, чтобы
он не оказался бутафорией, — `building-enforcement.md`.

**Почему это отдельный домен, а не `networking`:** источник истины другой — не внешние
исследования протоколов, а наблюдение за собственной средой. Проверяется прогоном на
настоящем транскрипте, а не сверкой источников.
