# Changelog

Все значимые изменения мозга агента-сисадмина. Формат — по [Keep a Changelog](https://keepachangelog.com/ru/),
версии — по [SemVer](https://semver.org/lang/ru/). Версия мозга — в файле `VERSION`,
релизы помечены git-тегами `vX.Y.Z`.

## [Не выпущено]

Разбор сессии 2026-08-04 независимым аудитором (`/retro`): 19 реплик оператора, 244 вызова
инструментов, восемь находок — три MUST, три NEVER, две MAY. **Закрыты все восемь.** Сессия
была боевой: ложная ночная тревога сторожа ботов, три починки инфраструктуры и системная
починка глухоты телеграм-бота, три собственные ошибки агента по ходу.

### Добавлено

- **ADR-0034 — чужой репозиторий определяется принадлежностью, а не способом доступа.**
  Правило «чужой git — не мой» жило в разделе про `/add-dir` и не сработало, когда
  продуктовые репозитории оператора попали в работу другим путём: агент склонировал
  репозиторий во временную папку, закоммитил, запушил и пересобрал образ руками мимо штатного
  скрипта выкатки. Теперь чужой — любой, кроме `sysadmin/` и папки инфры активного проекта;
  три обязанности до первой правки, включая «отказ штатного пути — сигнал оператору, а не
  повод обойти». Второй предохранитель в §0 рядом с первым.
- **ADR-0035 — бюджет ядра 42 000 → 46 000 Б, временно.** Ядро стояло на 97,8%, а трём
  находкам нужен якорь именно в ядре. Мера объявлена временной, триггер обратного хода —
  ближайшая ревизия персоны. Анти-храповик ADR-0016 сохранён. Замок проверен живьём в обе
  стороны и на границе.
- **Шаг 5.5 в `inventory-scan`** — сверка паспортов карточек: реальный адрес репозитория из
  клона на сервере, видимость через `gh`, нет `gh` — пишем «не проверено», а не догадку.

### Исправлено

- **Сторож инвентаря видел прямые команды, но не скрипты-обёртки.** Весь IaC-контур устроен
  обёрткой — настоящие `git pull` и пересборка живут внутри скрипта на сервере. Выкатка
  пересоздала контейнер, ответ закончился словами «инфраструктуру это не меняло», замок
  промолчал; при этом на безобидное `crontab -l` он срабатывал. Порядок починки соблюдён:
  сначала тест показал дыру четырьмя падениями, потом правка. Было 16 тестов, стало 22.
- **Cold Start заявлялся, но не выполнялся.** Теперь темп называется вслух до первой команды,
  пропущенный шаг — тоже. Заявление о чтении без чтения приравнено к «обновлять нечего» без
  проверки.
- **Реконструкция причины подавалась как факт.** Ловушек вывода стало три: правило было
  односторонним — модальности требовал вывод, снимающий проблему, но не вывод, который её
  объясняет. В reference — таблица «что кажется доказательством, а чем является на деле».
- **Незакоммиченная работа оператора — объект защиты Yellow.** `stash`/`pull`/`checkout`
  поверх неё требуют брифинга и паузы: `revert` её не вернёт, копия подтверждения не заменяет.
- **«Не нашёл» — утверждение о замере, а не о мире.** Ловушка 1 расширена с состояния на
  существование объекта. Три способа страховки перед словом «нет» и три частые причины
  ложного «нет»: каталог назван не как сущность, маска раскрывается до `sudo`, инструмент
  смотрит не в ту подсистему.
- **Паспорт карточки inventory сверяется живой командой** при её правке: устаревшее имя
  репозитория или «приватный» про публичный — не косметика.
- **Свежесть диагноза — часть проверки** (§3.11): действие по наблюдению старше нескольких
  минут требует переспроса системы; проверка в одной команде с действием не способна его
  отменить и потому проверкой не является. Плюс разведка чужого окружения перед проверками.

### Бюджет ядра

41 066 → 42 202 Б при поднятом потолке 46 000 (остаток 3 798). До поднятия свободно было 934 Б.

## [2.8.1] — 2026-07-25

Разбор той же сессии свежим аудитором (`/lore-retro`). Главное: **один из четырёх уроков
версии 2.8.0 был записан с неверной причиной**, и разбор это доказал по стенограмме.

### Исправлено
- **Неверный корень урока (F1).** Презумпция «память оператора ≠ факт» перекладывала
  причину на человека. Стенограмма показывает обратное: список каталогов «под чистку»
  составил сам агент — по единственному признаку «нет контейнера», — а оператор лишь
  согласился с этим списком и **прямо попросил перепроверить**. Настоящая причина: вывод о
  живости сервиса по одному слою исполнения, тогда как сервис жил systemd-юнитом.
  Правило переписано: сервис мёртв только после проверки **всех** слоёв. Добавлено
  мета-правило: прежде чем записать урок, объясняющий ошибку решением человека, сверься со
  стенограммой — иначе память копит недоверие к оператору вместо починки своей проверки.
- **Обход замка формулировкой (F3).** Замок остановил `rm -rf`, после чего тот же объект
  был удалён точечной командой — замок промолчал, и агент записал это оператору как
  аккуратное решение. По последствиям это обход процедуры. Введён критерий: ложное
  срабатывание — только когда команда **ничего не удаляет**; размер и происхождение объекта
  в критерий не входят. «Переформулировал так, что замок пропустил» = замок сработал.

### Добавлено
- **§3.3 «документ разошёлся с реальностью → правлю документ» (F2).** Приведение боевого к
  документу — отдельное изменение со своей зоной и брифингом. Поводом стал `chmod` на
  боевом `.env` с платёжными токенами, сделанный без брифинга ради честности документа.
- **Смена плана сверяется с требованиями, а не с изяществом находки (F4).**
- **Обещание автономной работы проверяется на исполнимость заранее (F5)** — «сделаю два
  шага без подтверждений» при закрытом для автовызова скилле.
- **Выгрузка окружения контейнера целиком выведена из зелёной зоны (F11):** вывод
  инструмента — такой же носитель, как файл; транскрипт переживает сессию и читается
  разборами.
- **Ссылки на ADR — с квалификатором репозитория (F10):** номера мозга и инфраструктуры
  уже столкнулись на 0025.
- **«Проверка соврала, а не система»:** негативный результат подтверждается вторым
  способом — `sudo ls каталог/*` раскрывает шаблон непривилегированной оболочкой и врёт «пусто».

## [2.8.0] — 2026-07-25

Разбор сессии установки веб-панели и ревизии инфраструктуры как кода. Тема выпуска —
**разрыв между «запущено» и «работает»**: три механизма за одну сессию отрапортовали
об успехе, не работая, и ни один не был бы найден без ручной проверки.

### Добавлено
- **Рефлекс §3.11 «живой тест вместо зелёного статуса»** + **ADR-0025**. Настроил защиту,
  проверку, бэкап, автозапуск или деплой — заставь сработать и посмотри результат.
  `active`, `healthy`, «деплой завершён» доказательством не считаются. Поводом стали три
  случая одной сессии: правило `fail2ban` показывало `active` и не ловило ничего
  (глобальный `backend = systemd` заставлял читать журнал вместо указанного файла лога);
  контейнер отдавал `healthy` при убитом ядром основном процессе (проверка щупала соседний
  процесс); деплой рапортовал успех, не применив изменений (`compose` не смог прочитать
  `.env` под непривилегированным пользователем, код возврата потерялся в конвейере).
  Не провёл тест — обязан сказать «живым тестом не проверял».
- **Чеклист «сервис выведен из эксплуатации»** (§3.10 полного слоя). Порядок добавления
  сервиса был расписан, обратного не существовало. Цена: шесть мёртвых vhost в
  репозитории, живой compose снятого мониторинга в списке деплоя, восемь инструкций со
  ссылками в пустоту. Чеклист перечисляет все места, где сервис оставляет хвост — от
  вызова в деплое до переменных у соседних сервисов.
- **Чек «дрейф IaC» в `/inventory-scan`.** Прежние чеки сравнивали inventory с
  реальностью; репозиторий конфигураций не сверялся ни с чем. Новый чек смотрит в обе
  стороны и сортирует находки по направлению: конфигурация, живущая **только на сервере**,
  опаснее лишней в репозитории — при восстановлении из git она просто исчезнет.
- **Презумпция «оператор вспоминает по памяти»** (`references/presumptions.md`).
  «Насколько я помню, это старый мусор» — гипотеза, а не факт; разрешение действовать
  снимает необходимость спрашивать, но не отменяет проверку. Кейс: каталог `sysadmin-bot`
  не порождал контейнера и по формальному признаку проходил как мёртвый — `systemctl`
  показал активный юнит службы, работавшей полторы недели.

## [2.7.1] — 2026-07-24

Правки по разбору сессии (`/lore-retro`, свежий субагент-аудитор). Замки стали точнее,
их контракт с конституцией — проверяемым.

### Исправлено
- **Замки блокировали read-only команды** (F4/F4+). Опасное слово внутри аргумента —
  `grep -rn "rm -rf" scripts/`, `truncate -s 0 /var/log/app.log`, `grep crontab file` —
  читалось как сама операция: три холостых срабатывания за день, после которых замок
  начинает восприниматься как шум. Лечение: команда разбирается **по сегментам**
  (`;`/`&&`/`||`/`|`), сегменты с read-only лидером (`grep`, `cat`, `echo`, `head`…)
  пропускаются целиком. Обёртки вроде `ssh host "rm -rf /opt"` по-прежнему ловятся —
  `ssh` не read-only. Плюс убрана необязательная группа в паттерне SQL-`TRUNCATE`,
  из-за которой матчилось любое слово `truncate`.
- **Строка-контракт дублировалась по памяти** (F3): в замке фраза подтверждения была
  набрана как «б[еёЕЁ]кап», канон C.3 пишет «бэкап» через «э» — замок не открылся бы
  никогда, а зелёные тесты этого не показывали (проверяли хук против той же выдумки).
  Добавлен тест, читающий фразу **из `CLAUDE.md`**; правило `/dev` §1.3а распространяет
  запрет на дублирование с чисел на строки-контракты.
- **Гейт находок отстал от маршрута** (F5): стоял на `retro/BACKLOG.md`, тогда как
  саморазбор переехал в глобальный навык, пишущий в `_retro/`. Матчер расширен на любой
  `*BACKLOG.md`; сырой отчёт аудитора и дайджест намеренно вне гейта — это стенограмма
  суждения, а не запись в память.

### Добавлено
- **Домен знаний `agent-runtime`** — устройство среды исполнения агента. Первая заметка:
  как отличить голос оператора в транскрипте Claude Code от вставок движка
  (`isMeta` / `sourceToolUseID` / `isSidechain` / `tool_result`). Знание нужно всем замкам;
  куплено дырой, которую не показали 24 зелёных теста на самодельных фикстурах.
- Тесты: 37 (красная зона) + 15 (гейт находок) + 16 (Stop-хук) + 21 (снимок без Docker).
  Каждый сьют проверяется **двумя прогонами подряд** — первый ничего не доказывает, если
  тесты делят глобальное состояние.

### Прочее
- Зафиксирован `.gitignore` с защитой `_retro/` (разборы сессий с дословными цитатами) и
  локального handoff-файла.
- Пять уроков сессии, верных для любого агента, ушли кандидатами в стандарт Loreground
  (вход кейса, пп. 15–19) — обезличенно.

## [2.7.0] — 2026-07-24

`/inventory-scan` перестал быть скиллом «только для Docker»: нативные VPS теперь получают
полноценный снимок и drift-report.

### Исправлено
- **Снимок падал на хостах без Docker (ADR-0024).** `dump-snapshot.sh` делал fail-fast
  «Docker не найден → exit 1», из-за чего владелец нативного VPS (VPN-сервер с 3X-UI +
  nginx, сервисы как systemd-юниты) вообще не мог синхронизировать inventory — только
  вручную. Теперь Docker — **определяемое свойство хоста**, а не предусловие запуска.
  Кейс с боевой инфры ученика; баг подпитывал главную болезнь — устаревание текстового
  зеркала, с которой борются ADR-0021/0023.

### Добавлено
- **`host_kind` в `meta.txt`** — три состояния вместо двух (третье вскрылось живым прогоном):
  `docker` (демон отвечает), `native` (Docker не установлен — контейнеров нет как **факт**),
  `docker-down` (CLI есть, демон молчит — состояние **неизвестно**, слепая зона, а не факт).
- **Секция `firewall.txt`** — UFW / iptables / nftables. Для нативного хоста это главный
  источник «что открыто наружу»; Docker-хостам полезна не меньше (`docker publish` обходит
  UFW, расхождение видно только при обоих срезах).
- **Регрессионный тест** `.claude/skills/inventory-scan/tests/test-native-host.sh` — 21
  проверка, имитирует хост без Docker урезанным `PATH`, офлайновый, сервер не трогает.

### Изменено
- Пропущенные секции контейнеров пишутся файлами с маркером `NOT_APPLICABLE: <причина>`
  (молчаливое отсутствие файла verify счёл бы битым снимком), `containers-inspect.json` —
  валидный `[]`.
- **Verify зависит от типа хоста:** общие ключевые файлы — `host-resources`, `host-services`,
  `firewall`; контейнерные проверяются только при `host_kind=docker`.
- **`health-flags`:** на хосте без Docker контейнерные метрики пишутся как `n/a` с причиной,
  а не как `0` (ноль читался бы как «проблемных контейнеров нет»). Добавлен `failed_units` —
  для нативного хоста главный индикатор здоровья.
- `SKILL.md`: предусловия, Шаг 4 (что писать в документы для `native` и `docker-down`),
  запись в «известные грабли».

## [2.6.0] — 2026-07-24

Третий замок — на самый тихий класс нарушений: карта инфраструктуры отстала от сервера.

### Добавлено
- **Stop-хук «инвентарь не отстаёт» (ADR-0023)** — `.claude/hooks/inventory-sync-guard.sh`.
  В момент завершения ответа сверяет текущий ход: были ли команды, меняющие инфраструктуру
  (`docker compose up/restart`, сети и тома, `systemctl restart`, `nginx -s reload`, `certbot`,
  `ufw allow`, `crontab`, правка конфигов) — и трогал ли агент `inventory/` либо пересобирал
  снимок/дашборд. Меняли без обновления → ответ не завершается, приходит напоминание §3.2.
  Два выхода: обновить документ **или** явно сказать оператору, что обновлять нечего.
  - **Read-only диагностика не считается изменением** — обход сервера хук не трогает.
  - **Останов ровно один раз на ход**: два независимых предохранителя (`stop_hook_active`
    и собственная метка по «сессия + ход») делают зацикливание невозможным.
  - **Fail-open** — сознательно иначе, чем в замке красной зоны: цена ошибки здесь
    расхождение документа, а не потеря данных, поэтому мешать работе хук не должен.
  - Метки старше двух суток хук удаляет сам (§3.10).
- **13 тестов** — `.claude/hooks/tests/test-inventory-sync-guard.sh`. Всего по трём замкам 49.

### Изменено
- Якорь §3.2 в ядре и `references/character-anchors.md` дополнены разделом про замок: что он
  видит, два законных выхода при остановке и чего он **не** видит (экзотические утилиты,
  правки оператора руками) — подпорка правилу, не замена.
- README: в карте файлов появился раздел `.claude/hooks/` с описанием всех трёх замков.

## [2.4.0] — 2026-07-24

Минор про **принуждение вместо просьбы**: самое ценное правило конституции (красная зона)
перестало зависеть от внимательности агента и стало свойством системы.

## [1.8.5] — 2026-05-28

Восстановлена работоспособность всех четырёх VPN-скиллов на свежих установках
3X-UI. С релиза панели v3.0.0 (начало 05.2026) в неё добавлен CSRF middleware:
голый POST на `/login` с username/password — как делал наш `scripts/lib-api/3xui.sh`
со старта VPN-блока — отбивается HTTP 403 с пустым телом. Ученик 5-го модуля
(Полякова) на свежей панели v3.1.0 это вскрыл, исключив все ложные причины
(form vs JSON, заголовки User-Agent/Origin/Referer/X-Requested-With,
nginx vs loopback — везде 403, рубит именно CSRF). До этого фикса
`/setup-vpn-panel`, `/configure-vpn-routing`, `/setup-server-proxy`,
`/generate-client-config` были мертвы на любой свежей установке — авто-вход
по API не работал, оставались только UI-клики или прямая правка SQLite.

### Исправлено
- **`scripts/lib-api/3xui.sh` функция `api_login`** переведена на двухшаговый
  протокол с автодетектом версии панели. Шаг 1 — GET страницы логина для
  получения CSRF-токена из HTML-меты `<meta name="csrf-token">` или
  отдельного endpoint `GET /csrf-token` (появился в v3.0.x). Шаг 2 — POST
  `/login` с заголовком `x-csrf-token`, если токен есть; без заголовка,
  если на сервере v2.x (CSRF не введён). При HTTP 403 на основном POST —
  принудительное обновление токена через `/csrf-token` и повтор. Bash-API
  обратно совместимо: старые вызовы `api_login --domain X --port N
  --web-path P --admin U --password-ref REF` продолжают работать на v2.x.
- **`api_call`** научен пробрасывать `x-csrf-token` на POST/PUT/DELETE
  в режиме cookie на v3.0+ панели (CSRF middleware режет не только
  `/login`, но и `/xray/update`, `/logout` и др.). На GET-запросах
  заголовок не отправляется — не нужен. Добавлен автоматический retry
  с обновлением CSRF-токена на ответе 403 (один раз, без увеличения
  delay) — закрывает случай «токен просрочился между логином и операцией».

### Добавлено
- **`scripts/lib-api/3xui.sh` поддержка Bearer-токенов** — новый параметр
  `api_login --bearer-token-ref <ref>`. Токен создаётся оператором в UI
  панели (Settings → Security → API Tokens) и хранится в менеджере паролей
  (`keychain:3xui-panel-<server>-token` или эквивалент в pass/bw/op). При
  передаче `--bearer-token-ref` пропускается двухшаговый логин и cookie —
  все вызовы `api_call` идут с заголовком `Authorization: Bearer ...`.
  Bearer-режим устойчивее CSRF (не зависит от страницы логина), но требует
  ручного создания токена и поэтому не дефолт. Скиллы по-прежнему могут
  логиниться по username/password — Bearer применяется только если в
  `sysadmin-config.json` указан `panel_api_token_ref`.
- **§3.8.11 в персоне `sysadmin.md`** — компактный указатель и в полных

- **Событие в `_live/timeline.md`** на 2026-05-28 «3X-UI v3.0.0+ ввёл

  (его там нет) и «заведение всех серверов подписки скопом» (= скачущий IP = бан).

## [1.2.0] — 2026-05-24

Автоматизации на карте инфраструктуры. По итогам реструктуризации Модуля 6 курса
«Архитектор ИИ-решений»: вместо «панели кнопок» ученик опирается на актуальную
Mermaid-карту от агента как на единый источник правды о том, что крутится само.
Значит, карта обязана отражать автоматизации — раньше они жили только в тексте.

### Добавлено
- **Сбор systemd-таймеров** (`dump-snapshot.sh` → `systemd-timers.txt`): на Ubuntu 24.04
  таймеры — основной способ расписания наравне с cron. Раньше собирались только
  enabled `*.service`, таймеры были полностью невидимы. `set +e` + honest-unknown
  при отсутствии systemctl.
- **Сбор скриптов-наблюдателей** (`watchers.txt`): долгоживущие процессы
  inotify/fswatch/watchdog — отличает «скрипт по расписанию» от «скрипт, слушающий
  событие». На карте это разные роли.
- **Новый inventory-документ `automations.md`** — сводная витрина всех автоматизаций
  независимо от механизма запуска (cron + systemd-timer + watcher + webhook + ручной).
  Колонки `name | trigger | schedule | runs | touches | log | status`. Колонка
  `touches` — источник связей для карты. Тип `automations` добавлен в шаблон
  `inventory-doc-template.md`.
- **Новая mermaid-диаграмма `automations.mmd`** (5-я): триггеры → автоматизации →
  что трогают (БД/сервисы/внешние API). Новый `classDef automation` (фиолетовый
  `#ede9fe/#7c3aed` — не конфликтует с app/db/mon/vpn/infra). Генерируется только
  при наличии автоматизаций (по образцу `vpn-architecture.mmd`).
- **Группа `automations` в `topology.mmd`** — факт наличия + ключевые связи на
  высоком уровне, без детализации триггеров (детали — в `automations.mmd`).
  Появляется только при непустом `automations.md`.

### Изменено
- **Правило синхронности §3.2 персоны** распространено на автоматизации: новая
  cron-задача / systemd-timer / скрипт-наблюдатель / pipeline или изменение того,
  что автоматизация трогает → обновить `automations.mmd` + группу в `topology.mmd`,
  иначе задача не закрыта.
- `inventory-scan/SKILL.md`: description, шаги 2/3/4/4.5/7, Verify-порог snapshot
  (≥14 → ≥16 файлов), 8 → 9 inventory-документов, 4 → 5 диаграмм.
- README + `diagrams/README.md`: состав диаграмм, условие генерации, цветовая семантика.

## [1.1.1] — 2026-05-24

Гибкость менеджеров паролей. По итогам диагностики пользователя на Windows: он
использует Kaspersky Password Manager, которого не было в закрытом enum схемы
(`keychain|bitwarden|1password|pass`) → конфиг невалиден → агент не запускался.
Та же болезнь жёсткого списка, что лечили в 1.1.0 (хардкод вместо гибкости).

### Добавлено
- В enum `secrets.manager`: `keepassxc` (скрипт установки уже был, но в enum отсутствовал)
  и `other` — для любого нестандартного менеджера (Kaspersky, Dashlane, NordPass, браузерный).
- Поля `secrets.manager_name` (имя нестандартного менеджера) и `secrets.cli_available`
  (умеет ли Claude доставать секреты автоматически).
- В `/sysadmin-init`: для `other` агент проводит ресёрч (WebSearch) — есть ли у менеджера
  CLI; честно объясняет расклад (нет CLI → пароли передаёшь руками) и предлагает
  альтернативу Bitwarden. Выбор за оператором. Запрет выдумывать наличие CLI.
- Агент учитывает `cli_available`: при `false` НЕ пытается доставать секреты сам, только
  указывает оператору, где взять руками (cold-start + setup-secrets-vault).

### Изменено
- `validate-config.sh`: jq-fallback принимает 6 менеджеров, требует `manager_name` при `other`.
  WARN про отсутствие check-jsonschema переформулирован в непугающий («необязательно»,
  не «ошибка») — jq-fallback достаточен, check-jsonschema остаётся опциональной надстройкой.

## [1.1.0] — 2026-05-24

Кроссплатформенность установки и принцип «не смог — скажи прямо». По итогам инцидента
с пользователем на Windows: настройка прошла криво, остался мёртвый `infra.md` вместо
папки `infra/` с `sysadmin-config.json` (причина — отсутствие `jq`, который не входит
в Git for Windows, и тихая импровизация агента вместо честной остановки).

### Добавлено
- **Адаптивный гейт окружения** (`_lib/ensure-local-env.sh`): динамический детект
  пакетного менеджера (brew/apt/dnf/yum/zypper/pacman/apk/nix/winget/choco/scoop/port)
  пробегом по PATH вместо привязки «ОС → менеджер». Авто-установка `jq` при отсутствии.
- **Универсальный fallback**: если пакетного менеджера нет — скачивание официального
  бинарника `jq` (github.com/jqlang/jq) под ОС+архитектуру. Работает на любой ОС без менеджера.
- **Финальная самопроверка** (`_lib/self-test-setup.sh`): после настройки агент тестирует,
  что всё реально работает (bash+jq, конфиг валиден, папка `infra/`, bridge-файл). При
  провале — честный вердикт «настройка не завершена, свяжись с разработчиком агента».
- **Конституционное правило C.9** в персоне: запрет на суррогаты конфига/инвентаря
  (никаких самодельных `infra.md`); «не смог → честный вердикт, не видимость работы».

### Исправлено
- Хардкод `/tmp/` заменён на `mktemp -d` (портируемо на Git Bash/WSL/macOS/Linux).
- FINAL CHECK после записи конфига: «Готово» печатается только если файл реально на
  диске и валиден — конец тихим «всё ок» при провалившейся записи.
- `find-config.sh`: `locate_sysadmin_root` понимает Windows-пути в bridge-файле
  (`C:\...`, `C:/...`, `/c/...`) + `cygpath -u`; единый резолвер без дублей grep-regex.
- Авто-добор `~/.sysadmin/bin` в PATH при каждом `source` helper'а — скачанный `jq`
  виден и в новом bash-процессе, и после перезапуска сессии.

### Изменено
- ADR-0002: hard cap ядра персоны поднят 400 → 410 (ради C.9).
- README + INSTALL: требования по окружению (bash обязателен, jq ставится автоматически),
  Windows-специфика. INSTALL клонирует последний тег динамически, без хардкода номера.
